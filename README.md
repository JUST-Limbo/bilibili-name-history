# B站曾用名（浏览器扩展）

在关注列表、UP 主页、视频页展示**本机备份过的**昵称历史。  
默认用页面 DOM 收集；可选 API 同步（有风控风险）。当前版本 `0.0.1`。

仓库：https://github.com/JUST-Limbo/bilibili-name-history

---

## 安装

### 环境

- Chrome / Edge（Chromium，Manifest V3）
- 已登录 [bilibili.com](https://www.bilibili.com)（用于识别自己的 UID，避免把自己记进库）

### 加载扩展

1. 克隆或下载本仓库到本地，例如 `c:\code\bilibili-name-history`
2. 打开扩展管理页：
   - Chrome：地址栏输入 `chrome://extensions`
   - Edge：地址栏输入 `edge://extensions`
3. 打开右上角「开发人员模式」
4. 点击「加载已解压的扩展程序」
5. 选择本仓库**根目录**（含 `manifest.json` 的那一层）
6. 确认扩展「B站曾用名」已启用；工具栏可固定图标，方便点开 Popup

### 更新扩展

本地代码有变更后：到扩展管理页找到本扩展 → 点「重新加载」。  
若新增了权限（如 `api.bilibili.com`），按提示确认授权。

### 卸载

扩展管理页 → 移除即可。本地昵称数据在浏览器扩展存储中，卸载后通常一并清除；重要数据请先「导出备份」。

## 使用

### 首次准备

1. 在浏览器打开并登录 B 站
2. 随意打开一个 B 站页面（首页 / 视频 / 空间均可），让扩展读取 Cookie / 顶栏头像中的 UID
3. 点击扩展图标打开 Popup，确认统计区能正常显示（尚未同步时人数可为 0）

### 看曾用名

扩展会在页面上的 UP 昵称旁尝试挂「曾用」徽章（仅当本机库里有该 mid 的历史昵称时）：

| 场景 | 说明 |
|------|------|
| 关注列表 | 列表项昵称旁 |
| UP 主页 | 空间页相关昵称链接旁 |
| 视频页 | 稿件 UP 等信息旁 |

曾用名**不是** B 站官方完整改名史，只来自你本机曾经收集到的快照。

### 收集关注列表（推荐顺序）

#### 方式 A：关注页右下角工具条（最直观）

1. Popup 点「打开我的关注列表」，或自行进入「我的关注」
2. 页面右下角出现「曾用名 · 本页扫描」面板
3. **扫描本页**：只记当前页可见关注
4. **自动翻页扫描**：自动点「下一页」并连续收集；可切到其它标签，由扩展后台驱动继续
5. 可看进度条、百分比、预计剩余时间；点「停止」可中断

#### 方式 B：Popup「DOM 翻页同步关注列表」（推荐一键）

1. 先在 Popup 选好**收集速度**（低速更稳 / 高速更快）
2. 点「DOM 翻页同步关注列表」
3. 扩展会在**后台**打开关注页、按速度翻页扫描，**结束后自动关闭该标签**
4. 不直接打关注列表业务 API，更接近正常浏览

#### 方式 C：Popup「API 同步关注列表」（高风险，慎用）

1. 会请求 `api.bilibili.com` 的 nav + 关注列表接口并翻页拉取
2. 点击后有确认框与风控说明
3. 短时间大量请求**可能触发验证码 / 临时限制**等；优先用 A / B

### Popup 其它功能

| 功能 | 说明 |
|------|------|
| 收集速度 | 低速 / 高速，作用于 DOM 自动翻页与 API 同步 |
| 自动同步 | 可选：本会话首次访问 B 站时；或距上次自动同步超过 N 小时后再访问时 |
| 自动同步方式 | DOM（后台开关注页扫完关页，推荐）或 API |
| 打开记录列表 | 浏览已记录的 UID / 昵称 / 曾用名 |
| 导出 / 导入备份 | JSON 备份与合并导入 |
| 清空本地备份 | 不可恢复；清空后约 10 分钟内暂停被动写回，避免仍打开的页面立刻填回 |

### 失败提示

同步失败时（例如关注列表改版导致选择器对不上），在已打开的视频页 / UP 主页 / 关注列表等页面右上角会出**飘窗**提示，便于发现并反馈。

---

## 注意事项

- 必须保持 B 站登录态；未识别到 UID 时 DOM/自动同步可能无法启动
- 优先 DOM 路线；API 仅作备用
- 低速可能降低风控概率，**不能保证**免风控
- B 站前端改版可能导致 DOM 选择器失效，需更新扩展后再用
- 清空备份前建议先导出
